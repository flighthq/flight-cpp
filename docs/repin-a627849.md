# Repin: flight 7e2fc7d → a627849

The `flight` pin moves from `7e2fc7df5378313ceaf21ba8d6ef39cc18a6f4ad` (2026-09-19) to
`a62784923f3be814463286c9fb28edfe6ab15789` (2026-10-01), 445 upstream commits. `flight-compiler` stays
at `2b687ea`, which is still upstream `main`. The pin moved in its own commit (`18661fe2`, "Move flight pin to a62784923f"), which was handed
off and landed first so the lanes could rehydrate. Everything below was done afterward against it.

Scope rule for this repin: nothing was regenerated or built SDK-wide. The only generation is the
package-scoped foundation closure, and the only compile is that closure's headers, at `-j2`.
`generated/` is therefore still the old-pin inventory, and `npm run sdk:check` will report drift
until each lane regenerates its own packages. That's expected, not a regression.

Four changes reach almost every package and account for most of the patch breakage:

- **Explicit `.ts` module specifiers** (`c250cb4b5`). Every relative import is now `'./x.ts'`, about
  15,000 of them. The compiler's relative resolver already tries the literal path, so lowering is
  unaffected. But any source patch whose hunk context includes an import line stopped applying.
- **Registry tables replaced with plain maps** (`77c4532b9`). `registryTable.ts` went from 256 lines to
  38, and `KeyedTable` is gone.
- **Renderer/material renames** (`a4f7bffd6`, `446bc9ea1`, `ebcb92646`, `3ed28ef18`, `4e82419a6`).
  `*GlMeshMaterialRenderer.ts` became `gl*MeshMaterialRenderer.ts`, `Renderer` became `NodeRenderer`,
  `draw*` became `render*`, and `begin/endEffectState` became `begin/endEffectPass`. Mesh material
  renderers merged into material renderers.
- **Types consolidation**: `Renderable` retired (`806334144`); `SurfaceMaterial` absorbed into
  `Material2D`/`Material3D` (`8bcf2e087`); storage result envelopes renamed to `Outcome`
  (`61b1d9dda`); `types` alone has 46 files added, 13 deleted and 740 modified.

Others with direct native consequences:

- `Camera2D` no longer carries a viewport; every helper takes width/height explicitly (`58db4a9da`).
- `RenderState` lost `renderTransform2D`, which is now passed to `render*Scene2D` (`27e179f0f`).
- `@flighthq/sdk` gained an SDK-owned module, `sdkHost.ts` (Host.compress / LZMA:
  `7f686d61f`, `1c6ad4b6b`, `35dc3c566`). It is re-exported relatively, which the pinned compiler
  rejected outright. See [the new compiler patch](#a-new-compiler-patch-was-required).
- Canvas hosting moved to `HostCanvasCapability` / `CanvasSurface` across render, scene2d-*, and
  host-web (`78cb9314b`, `949e71d05`, `a3f3b1f98`, `800f382fa`).
- The formats packages (scene2d, scene3d, skeleton2d) were split into per-handler modules for
  tree-shaking. That accounts for most of the added files below.

## Source patches: apply-check of all 153

The check mirrors generation: each dependency's patches are applied **cumulatively in manifest order**
to a scratch copy of the pinned tree, since many patches build on earlier ones. A single-patch check
gives the wrong answer. For example, every compiler patch "fails" alone even though the compiler pin
did not move. As a baseline, the same procedure at the old pin applies all 153 cleanly.

| | at old pin | at a627849, before rebasing | after this repin |
|---|---|---|---|
| compiler patches (pin unchanged) | 24 clean | 24 clean | **25 active** (+1 new) |
| flight patches | 129 clean | 61 clean, 8 fuzz-only, 60 fail | **75 active**, 42 pending, 12 dropped |

How the 129 Flight patches were resolved:

- **61 applied cleanly.** `baseCommit` was moved to `a627849`, and the text is unchanged.
- **12 were obsolete and are dropped** (entry and file both deleted), each with upstream evidence that
  the construct they rewrote is gone. See the table below.
- **12 recovered from a specifier-only rewrite.** Their context differed only by the new `.ts` import
  specifiers. Rewriting exactly those specifiers, and nothing else, makes them apply; the patch-file
  diff was checked to contain no other change.
- **4 foundation (GEN) patches were re-derived by hand**, since Q0 owns the foundation. Two are
  active; two apply but are held pending. See [Foundation](#foundation-regeneration-and-compile).
  - `node-exact-capability-runtimes`: 8 of its 16 files applied as-is. The rest were ported against
    current source (`traversal.ts` signatures to `NodeOf<Traits>`, `stageFit.ts` readonly view,
    `boundsRectangle.ts` direct `[EntityRuntimeKey]!` reads).
  - `node-exact-runtime-helper-boundaries`: applies unchanged once the above is in place.
  - `materials-exact-construction-owner`: re-derived for the new layout, where `createMaterial3D`
    replaced `createSurfaceMaterial` and its file is gone. Same transform: generic exact owner,

The resulting stack (25 compiler + 75 Flight) applies cleanly in manifest order at the pinned
revisions.

Applying cleanly is not the same as being effective. Generation's existing check flags a patch whose
refusal persists, and it ran for the foundation closure (below). A lane regenerating its own packages
is where the other rebased patches are judged.

### A new compiler patch was required

At `a627849`, `analyzeFlightWorkspace` throws before lowering anything:

```
CompilerInventoryError: SDK export lane @flighthq/sdk has unsupported external target: ./sdkHost.ts
```

So no generation at this pin, not even a single small package, is possible without a fix, and
upstream `flight-compiler` has nothing newer than `2b687ea`. The new
`compiler-sdk-lane-local-reexports` patch makes `readSdkExposures` skip relative re-exports, which
name SDK-owned modules and are not package exposures, instead of throwing. Every package exposure is
identical with and without it. Upstream request:
[compiler-requests/compiler-sdk-lane-local-reexports.md](compiler-requests/compiler-sdk-lane-local-reexports.md).

### Pending patches are declared, not skipped

`applySourcePatches` refuses any patch whose `baseCommit` is not the pin, which is the right default.
But with 40 patches still broken, it would block every lane's generation until all 40 were fixed. A
patch can now carry

```json
"pendingRebase": { "since": "<pin>", "lane": "GL", "reason": "…" }
```

A pending patch keeps its manifest entry, file and original `baseCommit`. It is never applied, and
every generation (`sdkGeneration.mjs`, `upstreamExampleGeneration.mjs`) prints the pending set grouped
by lane, so a run never reads as fully patched. The loader rejects a `pendingRebase` without `since`,
`lane` and `reason`, or one whose `since` equals its own `baseCommit`. A lane clears an entry by
rewriting the patch against the pin, setting `baseCommit`, and deleting `pendingRebase`, or by dropping
the patch if its refusal is gone.

Seven of the ten packages are at or above their old-pin state. Two have regressed.

**`node` regressed from 21/21 to 13/21. This is the one open foundation item.** At the old pin, node
was carried by three patches. One (`node-exact-runtime-and-owner-paths`) is active again. The other
two are re-derived and apply, but stay pending, because the main one, `node-exact-capability-runtimes`,
adds a runtime slot to `BoundsNode`/`Spatial2DNode`/`Transform2DNode`. Upstream has since made
`HasBoundsRectangleRuntime<Traits>` generic, with callbacks over `BoundsNode<Traits>`, so the slot
closes a type cycle: node → runtime → bounds callback → node. With the patch active, the pinned
compiler fails 17 `types` modules with `Maximum call stack size exceeded`. A run with
`ulimit -s unlimited` and `--stack-size=30000` was still lowering after 10 minutes and was stopped,
which makes this non-termination, not mere depth. It is the failure class already filed as
[recursive-type-evidence-nontermination](compiler-requests/recursive-type-evidence-nontermination.md).
Activating the patch trades 8 node modules for 17 types modules that every lane depends on, so it
stays held. The way forward is to re-derive it so the slot does not name the generic runtime (for

### Toolchain caveat
