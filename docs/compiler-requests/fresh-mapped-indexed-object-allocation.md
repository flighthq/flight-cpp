# Fresh mapped indexed-access allocation

The whole original Lottie image caller constructs `createSprite({ data: { texture: createTexture(...) } })`. Its `data` parameter is a partial indexed-access shape containing the Entity runtime symbol and texture. The backend selects `optional<Ref<entity_runtime_key_texture...>>` for storage, then allocates the narrower literal owner or emits raw aggregate braces because its nominal representation planner cannot classify the utility expression itself.

The bounded correction applies only at an object literal allocation. It requires a unique closed contextual shape, no duplicate/unknown authored keys, allowed omission of optional members, and compatible values for every supplied member. A matching discriminant alone is insufficient. The resolved object shape must emit exactly the same carrier as the contextual target. Normal object construction then allocates that owner once and uses its existing source-order evaluation and authored-own-key annotation.

Existing references never enter this path. It adds no structural-to-nominal recovery, copying, new runtime family, schema guard or source-body rewrite. A native fixture retains an original overload call, a computed-symbol member in the imported indexed shape, optional omissions and the original result reference; the existing anonymous lookalike control must remain refused. Earlier experiments with overload return substitution were discarded and are absent from the patch.

Qualification is recorded in `artifacts/original-json-exact21-closure-plan.json`. Header parsing and full image execution are separate obligations; no normal SDK output is regenerated by this work.
