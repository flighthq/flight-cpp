# Runtime semantics

The runtime exists where C++ standard-library behavior is observably different from TypeScript. Wrappers are justified by semantics, not by a desire to reproduce JavaScript method names.

## Initial invariants

- `Array<T>` and `Map<K, V>` are reference values. Copying a wrapper preserves backing identity; `clone()` explicitly creates new storage.
- Length construction keeps the runtime's array representation deliberately dense: `Array<T>(length)` materializes `length` value-initialized `T` elements rather than pretending that C++ can observe JavaScript holes. Floating lengths use JavaScript's array-length domain (finite integers from zero through 2^32 - 1) and reject other values; actual allocation remains subject to address-space and allocator limits. This choice means hole-sensitive operations are outside the dense profile, while length, indexing, iteration, and writes have one explicit representation.
- `Array<T>::at` and `Map<K, V>::get` return absence rather than throwing for a missing index or key.
- Array inclusion and map key identity use SameValueZero: NaN equals NaN and positive and negative zero are the same value.
- Map iteration retains insertion order. Updating an existing key does not move it.
- `Undefined`, `Null`, and `Presence<T>` keep the two TypeScript sentinels distinct from one another and from an ordinary value.
- `String` stores UTF-16 code units, so length, indexing, slicing, splitting, and unpaired-surrogate behavior do not depend on the machine encoding. UTF-8 conversion is an explicit boundary.
- `Set<T>` shares Map's SameValueZero and insertion-order rules. Typed-array copies and `subarray` share a fixed backing store, while `slice` copies; clamped bytes use saturating ties-to-even conversion. `ArrayBufferLike` retains ordinary, shared, or host-owned memory together with stable backing identity, lifetime, mutability, and concurrency policy. Typed arrays and `DataView` keep that backing without copying.
- `Blob` copies its input parts into immutable shared byte storage. String parts use UTF-8, MIME types are printable ASCII normalized to lowercase, byte slices use JavaScript's signed-index rules, and text decoding follows the runtime's UTF-8 replacement behavior.
- URI component encoding operates on UTF-16 scalar values and emits uppercase UTF-8 percent escapes; decoding rejects malformed escapes and UTF-8. Base64 uses the browser binary-string domain, strips the specified ASCII whitespace while decoding, and rejects input code units outside one byte while encoding.
- Stream copies share identity and one lock state. Native sinks and sources return `Task` values for writes, close, abort, reads, and cancellation; released readers and writers reject further operations. The current contract does not yet model Web Streams backpressure, piping, transforms, or teeing.
- Shared container and binary-view handles use logical constness: a compiler-emitted value capture cannot rebind its handle, but it can mutate the JavaScript object referenced by that handle. `TextEncoder` converts UTF-16 scalar values to UTF-8 and replaces each unpaired surrogate with U+FFFD.
- `WeakSet<K>` and `WeakMap<K, V>` copy as aliases, compare keys by object identity, remove expired entries opportunistically, and never retain or enumerate keys. Flight references and `Array<T>` provide recoverable weak ownership; host handles require an explicit policy with the same lifetime and identity guarantees. A policy must supply a non-owning weak token, recovery, stable identity, hash, and equality for its exact key type; primitive and unapproved key types do not instantiate a weak collection. Values remain their represented C++ type, including references and structural rows. `ErasedValue` is a checked type-tagged compatibility carrier for the exact `WeakMap<object, unknown>` lane, not an unchecked pointer fallback.
- `Task<T>` is copyable and shares one settlement. Observers run through a non-reentrant executor, completed tasks can be awaited repeatedly, and exception or non-exception rejection values retain their identity and type.
- `Date` applies ECMAScript-style finite millisecond clipping and stores an epoch instant. The initial calendar projection is UTC-only and is limited to the range represented by C++20 `std::chrono::year`; local-zone `getFullYear` behavior is not yet claimed.
- `number_to_fixed` follows `Number.prototype.toFixed`, rounding the double's exact decimal expansion rather than asking printf for the final precision: printf rounds a tie to even and the language rounds it away from zero, so `(2.5).toFixed(0)` is `"3"`. Negative zero produces no sign while a negative value that rounds to zero keeps one, and a magnitude at or above 1e21 falls back to the number's own string.
- `round` follows `Math.round`: nearest-integer ties move toward positive infinity, inputs from -0.5 through negative zero retain a negative-zero result, and NaN and infinities pass through unchanged.
- `RowRequired<Row>` is the inverse of `RowPartial<Row>`, not its absence: it names every member of the row as present. The subject's storage is unchanged -- a member the subject declared optional stays an `std::optional` in the object -- but reading it through a required row yields the value rather than the optional, and a row that does not in fact hold one throws instead of handing back an empty optional to invoke. Because it is an inverse, it overrides an inner `RowPartial` rather than inheriting from it, so `Required<Partial<T>>` names every member present; readonly-ness passes through in both directions.
- `Ref<T>` is `shared_ptr<T>` for a record and `T` for a value shape, and it answers the same way whether or not `T`'s definition is in scope yet. Two records that name each other are representable: the completeness question is asked through overload resolution rather than through a class template specialization, because a specialization cannot be used while it is still being selected and the recursive query re-enters exactly that. A type that names itself through `Ref`, directly or through another type that names it back, must derive from `ReferenceEnabled` -- it is asked about while incomplete, when the only available answer is "record", and `make_ref` refuses a type where that answer and the marker disagree rather than letting one spelling mean two types.
- `Any` is the erased dynamic value for the `any` and `unknown` type positions the SDK leaves unconstrained. It carries every ECMAScript language type the runtime has as its own alternative, so a value written `unknown` that is a number stays a number rather than becoming an object reference. `typeof` reports the language's own results, including `object` for `null` and `function` for a callable. `===` never coerces, `SameValueZero` matches NaN with NaN so an erased value can key a `Map`, and `Object.is` separates positive from negative zero. Object, callable, and host values compare by reference identity and come back only at the type they went in as.
- A missing entry and an entry whose value is `undefined` are different things, and stay different. `Any` holds `undefined` as a present value; `AnySlot` — `std::optional<Any>` — reports "no such entry". `Record::get` and `AttachedProperties::get` already return the latter, so both facts survive a round trip through a container.
- `AttachedProperties` gives an object symbol-keyed properties that every projection of that object shares. One owner is resolved per object identity, keyed on the object's address rather than on its static type, so a typed row, a structural row, and an erased `Ref<void>` all read and write the same entries. Attachments last as long as the object, not as long as the view that wrote them, and an address reused by a later object never inherits the earlier one's entries.
- `structured_clone` deep-copies the runtime's own value domain. Sharing is preserved — two members that referenced one object still reference one object afterwards — and a cyclic reference graph clones into an equally cyclic one, because each clone is recorded before its contents are copied. Symbols and callables are refused with `DataCloneError`, as they are in JavaScript.
- `TaskFulfillment<T>` and `TaskRejectionResult` are the two arms of a settled result, separately. `TaskSettlement<T>` carries both a value and a rejection because it is the union of the arms; neither arm carries the other's member, and `as_fulfilled`/`as_rejected` narrow without inventing one.
- `CanvasRenderingContext2D` owns the half of the Canvas 2D contract that is the same on every device: the drawing-state stack, the current transformation matrix, path construction, dash lists, gradient stops, and pattern parameters. Path segments retain the transform that was in force when each was added, so a transformed arc stays an exact arc instead of being flattened at a tolerance the runtime cannot know.

## Deliberate gaps

The task runtime implements `flight-runtime-task-capability-abi/1`: synchronous executor invocation, first-call-wins settlement, task assimilation, queued `then` and rejection recovery, awaited `finally` cleanup, ordered `all`/`join_all`, ordered non-rejecting `all_settled`, coroutine suspension and resumption, exact rejection, and `void`. `TaskSettlement<T>` preserves status plus the exact fulfilled value or rejection reason, and `all_settled_tasks` bridges semantic arrays to that carrier. `QueueExecutor` provides the deterministic default and `ExecutorScope` installs a host executor while tasks are created or resumed. An executor must enqueue rather than invoke `post` reentrantly; host integrations own the event-loop wakeup and thread-affinity policy. Cancellation and structured concurrency remain separate future capabilities rather than being implied by Promise compatibility.

`Array<T>` currently requires copyable elements for operations that return copied values. `Map<K, V>` uses an ordered linear store to make identity and order correct before optimization; a later index must preserve those results exactly. Object keys will need an explicit reference-identity trait rather than accidental value equality.

String case conversion is exact for ASCII and delegates non-ASCII input to the active `UnicodeService`. The core never consults the process locale. Production hosts must provide a Unicode implementation with a pinned Unicode-data version and conformance tests for expansion, supplementary characters, Turkish casing, normalization non-equivalence, and unpaired surrogates.

External `ArrayBufferLike` storage must remain valid through its shared owner and suitably aligned for each typed view. Read-only backing supports `DataView` reads and rejects writes; mutable typed arrays reject read-only backing at construction. Shared-memory policy is observable metadata, while callers remain responsible for synchronization. Atomic operations, detachment, resizable buffers, and JavaScript's full shared-memory access model remain outside the current runtime contract.

`Any` has no `bigint` alternative, because the runtime has no arbitrary-precision integer; a host that needs one carries it as an external value. Loose equality (`==`) and ordering of non-primitives are deliberately absent rather than approximated: ECMAScript defines both through `ToPrimitive`, this runtime has no prototype chain to consult, and a fabricated `"[object Object]"` would be an invented answer rather than a missing one. `relational_compare` therefore throws `TypeError` for an object, callable, host, or symbol operand, and implements the abstract relational comparison exactly over the primitive domain.

`structured_clone` has no definition for an arbitrary aggregate, and that is a refusal rather than an omission: C++20 cannot enumerate an aggregate's members, so a default that copied the aggregate would produce a shallow copy wearing a deep copy's name. Such a type fails to compile with a message naming `structured_clone_traits`, which is the customization point a generated or host type specializes. An erased `Any` holding an object or a host value is refused at runtime for the same reason — the handle carries no clone definition.

`CanvasRenderingContext2D` is a contract, not a renderer. flight-cpp ships no rasterizer and does not pretend to: a context is created with a `Canvas2DRasterizer` a host supplies, and a context without one throws `Canvas2DUnattachedError` from every operation that would have produced or read pixels while continuing to maintain the state and transform the runtime owns. Gradients and patterns retain their parameters and their identity; interpolating them is the rasterizer's. `drawImage` and `createPattern` accept any host source type through `Canvas2DImageSource`, which carries the host's own value with its type intact and never interprets it. The context's public attribute members mirror the Web IDL attributes and are republished into the shared drawing state before every operation that consumes them, because the compiler passes a bound context by value; `getLineDash`, `save`, and `restore` therefore behave correctly within a call, and a context handed to a callee shares its rasterizer, its state stack, and its identity.

`FontFace` is a portable value handle, not a font system. Flight constructs one in portable code — `new FontFace(family, source)` in `packages/font/src/_fontFaceLoad.ts` — so it cannot be an opaque handle only a host can mint, and it is not an Entity: a face carries no runtime key and no identity-keyed side table, so a `HostFontLoadingCapability` that receives one through `addFontFace` receives that object and nothing else. The gap is that this dependency-free runtime has no font parser and therefore cannot decide whether a source is a usable face. `load()` settles through the loader a profile installs with `set_font_face_loader`; with no loader installed it **rejects**, naming the missing capability, and the face's status becomes `"error"`. It does not resolve, because the next thing the caller does is hand the face to the host as though it had loaded. A rejected load carries the host's own reason unchanged rather than one the runtime invented.

A **plain host capability** needs no new runtime primitive, and this is the finding rather than a plan. A method-bearing plain interface such as `HostGlCapability` emits as an ordinary struct whose members are `std::function`, reached as `StructuralRef<RowReadonly<RowOf<Ref<Capability>>>>` and invoked through `row_get<RowKey<"acquire">>(row)(args...)`. An **optional** object capability — `readonly context?: HostGlCapability` — emits as `std::optional<Ref<HostGlCapability>>`, so absence and a present reference are two states of one optional and nothing compares a reference against `flight::undefined`. No Entity runtime key and no identity-keyed side table stand behind either: the row reaches the provider's own object. `npm run host-capability:oracle` compiles and runs the pinned compiler's own output for that shape — present and absent, two methods invoked, a returned callable round-tripped — so the contract is held by a test rather than by assertion.

Capability status in `flight/contract.hpp` is machine-readable but intentionally coarse during incubation. `initial` means an implementation and local semantic tests exist; it does not mean the backend as a whole is production-ready.

## Profile-specific external type policy

| Family | Classification | Runtime decision |
| --- | --- | --- |
| WebGL scalar aliases and object handles | Concrete SDL implementation | Numeric WebGL aliases, including `GLsizei`, use the source `number` representation. SDL WebGL objects retain their native owner and expose explicit weak-key policies; the map never owns the object. |
| Web Audio | Profile-specific unavailable capability | SDL's explicit audio-device provider is not the browser `AudioContext` decode/node graph. `AudioContext` remains unbound until a host supplies that capability rather than receiving an inert placeholder. |
| Intl | Concrete locale-neutral subset plus intentional refusal | Collator, date/time, number, plural, relative-time, and list operations retain the documented locale-neutral baseline. `Intl.Segmenter`, `Intl.SegmentData`, locale arguments, segmentation options, and segment iterators remain refused because this dependency-free runtime ships neither Unicode segmentation tables nor a host segmentation provider under those ambient names. |
| DOM and media | Opaque capability handles plus intentional refusal | SDL image/video/bitmap/offscreen/frame types are the existing `ImageSource` capability handle and carry stable weak identity. `DOMException` is a concrete portable value. Browser constructors and a general `Navigator` remain unbound: constructing or exposing those surfaces would claim browser services the SDL profile does not provide. |
| WebGPU | Concrete SDL handle/value implementation | Reference-counted GPU objects retain typed native handles with explicit weak policies. Closed WebGPU string domains such as `GPUCanvasAlphaMode` remain `flight::String`; represented descriptor records retain their typed fields. |

The compiler's built-in flight-cpp symbols own static members of `Array`, typed arrays, `ArrayBuffer`, `Object`, and `Promise`. External profile manifests are appended after those symbols and therefore cannot augment their members. The runtime implements `array_from`, typed-array `from` and `bytes_per_element`, `is_array_buffer_view`, `object_values`, and `all_settled_tasks`; publishing those exact ambient members remains a compiler binding change rather than a permissive downstream duplicate.
