# `insert-using-declaration` must not match a name that appears only in a comment

A repository tooling defect in `scripts/emissionRepairs.mjs`, not a compiler defect.

An `insert-using-declaration` repair fires when its symbol appears in a generated header. The test is a word
boundary match over the whole file, comment lines included. Every generated header begins with
`// Generated by @flighthq/tool-compiler from <package>/<source>#<Symbol> at <revision>`. A refused declaration's
TypeScript is also quoted in `// NOT GENERATED` comment blocks. So a repair keeps "applying" to a header that
names its symbol only in a comment:
- it inserts a `using` declaration;
- it hoists that symbol's defining include into the header.

The expiry check (`obsoleteRepairs`) never sees such a repair as unused.

## How it showed

At flight a627849, `@flighthq/types` no longer declares `Renderer`, `Renderable`, `RenderEffectPadding`,
`RegistryTable`, `CanvasRenderSurface`, `CanvasRenderSurfaceCreator` or `CanvasRenderSurfaceOptions`. The
repairs naming them still fired, for example:
- on `flight/render/renderer.hpp`, whose comment reads `...renderer.ts#Renderer`;
- on `flight/registry/registry_table.hpp` (`...#RegistryTable`).

Each inserted an include of a header that no longer exists, and `pkg:generate`'s dangling-include guard
refused the registry group's move. The entries were removed by hand during the a627849 migration
(see [repin-a627849.md](repin-a627849.md)). The matcher that let them survive was left as it was.

## Reproduction

```js
const header = '// Generated by @flighthq/tool-compiler from @flighthq/x/packages/x/src/renderer.ts#Renderer at abc. Do not edit.\n'
  + '#pragma once\nstatic_assert(flight::runtime_contract.cpp_abi == 1, "...");\n\nnamespace flight::x {\n\ninline void f() {}\n\n} // namespace flight::x\n';
applyEmissionRepairs([{ kind: 'insert-using-declaration', symbol: 'Renderer', ... }], [{ path: 'flight/x/renderer.hpp', contents: header }]);
// before the fix: applied to 1 file, `using flight::types::Renderer;` inserted
```

Both shapes of the kind reproduce it: the single `symbol` form and the `symbols` list form.

## Required behavior

A symbol counts as used only where it appears outside comment lines. A repair whose symbol appears only in
comments matches nothing, and a full run then reports it as obsolete. Two things stay unchanged:
- a repair that declares `requiredText`, which deliberately witnesses a `NOT GENERATED` marker;
- every other repair kind.
