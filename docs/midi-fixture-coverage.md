# @flighthq/midi -- upstream fixture coverage and the blocked surface

`@flighthq/midi` is `partial` at a627849: 5 of 7 modules emit, 3 of 7 headers compile, and the package is
**not shippable**. This records every upstream case, what covers it, and -- for the blocked ones -- the
exact boundary that stops it, rather than a broad label.

`tests/generated_midi_test.cpp` exercises the two modules that compile. It was EXTENDED, not replaced.

## Why 34 cases are blocked, per module

**`midiPermission` (1 case) and `midiResource` (5) are reachable.** Both modules emit whole and their
headers compile. All six cases carry assertions; see the table below.

**`midiPort` (11 cases) is blocked at the module.** `midi_port.hpp` is a best-effort placeholder; the whole
of `midiPort.ts` was refused with `captured referent mutation of state requires a shared C++ reference
representation`, tagged `unruled [compiler-restriction]`. No declaration exists to call, so none of the 11
cases has a subject. Filed as `docs/compiler-requests/captured-referent-mutation.md`.

**`midiSubscription` (16 cases) is blocked at the header, by a narrower cause than its own gap.** The
module is a PARTIAL emission: four module-local functions were omitted, each marked `NOT GENERATED` in the
header with its source line and refusal id:

| omitted | source line | refusal |
| --- | --- | --- |
| `untrackMidiSubscription` | 279 | `cpp-optional-property-call-missing-callable-result` |
| `detachMidiSubscription` | 217 | `cpp-contextual-union-value-type-unrepresented` |
| `attachMidiInputMessageSubscription` | 39 | `cpp-contextual-union-inequivalent` |
| `attachMidiPortStateSubscription` | 54 | `cpp-contextual-union-inequivalent` |

But the compile blocker is not those four. The RETAINED code still calls the omitted
`untrack_midi_subscription` (header line 164, from source line 275), so the header fails at a name that
never existed and nothing that includes it can build. Filed as
`docs/compiler-requests/optional-property-call-result-evidence.md` (why the four cannot be lowered) and
`docs/compiler-requests/retained-declaration-calls-omitted-callee.md` (the retained call to an omitted
callee -- midi is that request's second measured site). The distinction matters: fixing the header
compile does NOT make these 16 cases reachable, because four of the functions they specify would still not
exist.

**`midiAccess` (7 cases) is blocked transitively.** Its own module emits, and its own declarations are
present, but `midi_access.hpp` re-exports `midi_subscription.hpp`, so it inherits that failure. `contract.hpp`
and `_internal_index.hpp` fail the same way. No separate defect.

## What was added to the test, and why it was missing

The existing assertions were not wrong, but four of them did not test the claim their case title makes:

| case | title claims | what was asserted before | now asserted |
| --- | --- | --- | --- |
| `getMidiPermission` | "preserves shared query outcomes" | the success arm, and a rejection becoming `operation-failed` | the middle call the fixture makes: a capability that RESOLVES the reason-only arm keeps its own reason `unsupported`, and one query is one provider call |
| `getMidiAccessResourceState` | "only state retained for the exact access identity" | the same access before and after retaining | a SECOND access is not answered for once another was retained |
| `getMidiPortResourceState` | "does not collapse distinct port identities with matching metadata" | an input port and an output port (which differ in kind) | two INPUT ports with byte-identical `id`/`manufacturer`/`name`/`version` keep distinct states |
| `retainMidiOutputPortResourceState` | "without an input-message ledger" | the arm kind and its operations | the output arm's `state_subscriptions` set is empty |

Two of these are the difference between testing a property and testing its name: the port case previously
compared an input against an output, which a value-keyed map would also pass.

A latent crash was fixed at the same time. `const auto previous = *input_arm;` dereferenced a possibly-null
arm, so when the arm lookup was mutated away the suite ABORTED instead of recording failures -- which would
have hidden every later assertion behind it. It is now guarded, and the mutation that provoked it
(`port_states.set` keyed by a fresh port) now reports two clean FAIL lines.

## What would make the other 34 reachable

Nothing on this side. Three already-filed compiler requests cover it: `captured-referent-mutation.md`
(whole `midiPort` module), `optional-property-call-result-evidence.md` (the four omitted
`midiSubscription` functions), and `retained-declaration-calls-omitted-callee.md` (the retained call that
breaks the header). A hand-written override could supply `midiPort` and the four functions, and that is
the only path to shippable here -- but per the package's rules an override is the last resort, it carries a
copy with `derivedFrom`/`status`/`remaining`, and it would be supplying two modules' worth of real
behaviour (27 cases) rather than a seam. It is decision for the user, not a step taken unilaterally.
