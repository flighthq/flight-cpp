# 3D lane parity inventory

_Upstream readings taken at Flight `a62784923f3be814463286c9fb28edfe6ab15789` and flight-compiler `2b687eaf6b631e0fa4d7d6e18dad93b845f99633`, this checkout's pin (`dependencies.lock.json`)._

This is the Q2 parity inventory for the 3D lane: for each package, the upstream Vitest tests, the
behaviors they assert, what local CTest already covers, and which behaviors are web-only. It exists
so Phase 1 lane work can be planned against a known list of upstream guarantees rather than
rediscovered package by package.

## Provenance and method

**Two revisions are in play, and they are not the same one.**

- The **upstream columns** (test files, asserted behavior groups, `it`/`expect` counts) are read from
  the pinned Flight checkout that `npm run rehydrate` materializes into the gitignored
  `.dependencies/`, at the **Q0 pin** in the header above. Upstream tests are the Vitest files at
  `.dependencies/flight/packages/<package>/src/*.test.ts`; the *Asserted behavior groups* column is
  the set of `describe(...)` titles in each file, which name the behaviors that file asserts.
- The **inventory columns** (source / emitted / refused modules) are read from the committed
  `generated/manifest.json` and `generated/refusals.json`. That tree was generated at the *previous*
  pin (`7e2fc7df`); the Q0 re-pin moved the lock but did not regenerate the tree, and regenerating it
  is out of scope for this document. Treat those three columns as the current committed inventory,
  not as a reading of the new pin.

The local-coverage column comes from the repository's own CTest registrations. Where a test carries a
`flight_cpp_package_test_labels` label set, that label is the authority for which package the test
covers; example coverage is taken from the header each `examples/upstream/*.cpp` port includes.

**No build was run and no whole-SDK operation was performed to produce this document** — it is read
from the pinned sources and the committed generated tree only.

## Reconciliation note

Lane membership here was corrected against the approved contract table after an earlier draft
over-included and under-included packages. The earlier draft treated packages the 3D lane merely
*consumes* — `materials`, `geometry`, `collision`, `spatial`, `camera`, `camera-controls`,
`lighting`, `shading`, `scene3d-wgpu`, `gizmo` — as members; they are not, and they are now listed
only as consumed dependencies (see *Packages this lane consumes but does not own*). The Q0 part 1
re-pin to `a627849` added no package to either lane: the thirteen packages newly present upstream at
that revision (`host-capacitor`, `host-electron`, `host-tauri`, `host-web`, `requirement`,
`requirement-catalog`, `requirement-codegen`, `sdk`, `tool-capture`, `tool-manifest`,
`tool-pipeline`, `tool-registry`, `vite-plugin-manifest`) are outside both lanes. `textshaper-canvas`
was removed upstream and is not a member.

## Lane membership

The lane is **exactly** these 9 packages, per the approved contract table:

`@flighthq/scene3d`, `@flighthq/scene3d-gl`, `@flighthq/scene3d-formats`, `@flighthq/scene3d-resources`, `@flighthq/mesh`, `@flighthq/skeleton3d`, `@flighthq/physics3d`, `@flighthq/physics3d-abi`, `@flighthq/picking`.

Nine packages: the three-dimensional scene graph (`scene3d`), its GL backend and asset
side (`scene3d-gl`, `scene3d-formats`, `scene3d-resources`), mesh and skinning (`mesh`,
`skeleton3d`), physics and picking (`physics3d`, `physics3d-abi`, `picking`). The GL+2D lane owns
`render`, `render-gl`, `effects-gl` and every `scene2d*` backend; `scene3d-gl` is the Scene3D GL
backend and is here.
